\section{Key Features}
\label{sec:key-features}

Stockrium provides a connected set of features for exploring the Vietnamese stock market, examining financial evidence, obtaining multi-agent analysis, and testing supported analytical configurations through Stockrium Lab. The following subsections specify the principal user-visible capabilities using a consistent use-case format. Chapter~4 presents their architecture and implementation, while Chapter~7 demonstrates the implemented interfaces.

\subsection{Authentication and Account Management}
\label{subsec:authentication-account-management}

\noindent\textbf{Use Case Name:} Manage Account, Session, and Personal Preferences

\noindent\textbf{Actor:} Guest; Authenticated Investor

\noindent\textbf{Pre-Condition(s):} The mobile application can reach the backend. Registration requires an email address that is not already assigned to another account.

\noindent\textbf{Post-Condition(s):} A verified account and authenticated session are created, or the investor's selected profile, investment horizon, language, theme, or watchlist changes are persisted. Signing out invalidates the active session and removes the locally stored tokens.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The guest opens the application and selects account registration.
    \item The guest enters the required account information and receives an email verification OTP.
    \item The guest submits the valid OTP and completes account verification.
    \item The investor signs in with the registered email and password.
    \item The system creates a session and opens the authenticated application.
    \item The investor reviews or updates personal preferences and watchlist symbols.
    \item The system validates and persists each authorized change.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item An existing user signs in directly with a password or Google Sign-In.
    \item A forgotten password is reset after successful OTP verification.
    \item An invalid, expired, or repeatedly incorrect OTP is rejected; the user may request a new code subject to the resend policy.
    \item An expired access token is renewed through the valid refresh session; otherwise, the user returns to sign-in.
    \item Duplicate watchlist operations are handled without creating duplicate records.
\end{itemize}

\subsection{Market Overview and Stock Discovery}
\label{subsec:market-overview-discovery}

\noindent\textbf{Use Case Name:} Explore the Market and Discover a Stock

\noindent\textbf{Actor:} Authenticated Investor

\noindent\textbf{Pre-Condition(s):} The investor is authenticated and prepared market, industry, and current-price records are available to the backend.

\noindent\textbf{Post-Condition(s):} Market information is displayed. When the investor selects a stock, its symbol becomes the active stock context and a successful search is recorded in the user's recent history.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The investor opens the Overview or Market tab.
    \item The system displays principal indices, market movement, industry information, and available stock collections.
    \item The investor browses a collection or searches by stock symbol or company name.
    \item The system returns the matching securities and recent search entries.
    \item The investor selects a security.
    \item The system records the search when applicable and opens the corresponding stock context.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item The investor enters a stock context from the watchlist, a news article, an industry view, or a market-highlight collection.
    \item An unknown query produces a controlled empty state instead of an invalid navigation target.
    \item If part of the market response is unavailable, the interface presents the available sections and an appropriate loading, empty, or retry state.
\end{itemize}

\subsection{Stock Details and Interactive Technical Charts}
\label{subsec:stock-details-charts}

\noindent\textbf{Use Case Name:} Inspect Stock Information and Technical Charts

\noindent\textbf{Actor:} Authenticated Investor

\noindent\textbf{Pre-Condition(s):} The investor has selected a supported stock symbol and the backend contains at least one applicable market or company record.

\noindent\textbf{Post-Condition(s):} The selected stock's available price, company, fundamental, technical, and news evidence is presented. No market or user-owned financial record is modified.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The investor opens a stock from search, market discovery, news, or the watchlist.
    \item The system loads the current quote, historical OHLCV series, and company profile for the selected symbol.
    \item The investor selects a chart type and time period.
    \item The system renders the price and volume series and the selected technical indicators.
    \item The investor reviews company information, financial statements, fundamental measures, related news, and similar securities.
    \item The investor may proceed to the analysis configuration while retaining the same stock context.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item The investor switches between area and candlestick charts or enables different technical indicators.
    \item The investor selects a related security and the page reloads using the new symbol.
    \item A missing company, financial, indicator, or news section is shown as unavailable without preventing the remaining sections from being inspected.
\end{itemize}

\subsection{Financial News Exploration}
\label{subsec:financial-news-exploration}

\noindent\textbf{Use Case Name:} Explore Financial News

\noindent\textbf{Actor:} Authenticated Investor

\noindent\textbf{Pre-Condition(s):} The investor is authenticated and the scheduled news pipeline has stored one or more processed article records.

\noindent\textbf{Post-Condition(s):} The selected article, its available metadata, summary, sentiment, and related stock or category links are displayed. The investor may open a related stock context.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The investor opens the News tab.
    \item The system displays available business, macroeconomic, and topic-based article collections.
    \item The investor selects a category or article.
    \item The system presents the article content and its available summary, publication information, image, and sentiment label.
    \item The investor reviews related securities or returns to the article collection.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item The investor opens a stock-specific article from the corresponding stock-detail screen.
    \item A macroeconomic article may be displayed without an individual-stock association.
    \item A missing image, summary, or association is omitted while the remaining stored content remains accessible.
\end{itemize}

\subsection{Investment-Horizon Profile and Configurable AI Analysis}
\label{subsec:configurable-ai-analysis}

\noindent\textbf{Use Case Name:} Configure and Request Multi-Agent Stock Analysis

\noindent\textbf{Actor:} Authenticated Investor

\noindent\textbf{Pre-Condition(s):} The investor is authenticated, a supported stock is selected, and at least one analytical evidence source is usable. Automatic mode additionally requires a saved investment horizon.

\noindent\textbf{Post-Condition(s):} A structured \textit{Buy} or \textit{Wait} assessment is displayed with confidence, component scores, and explanations. An accepted \textit{Buy} may also include entry, take-profit, stop-loss, and maximum-holding information. No order is created or executed.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The investor opens analysis configuration for the selected stock.
    \item The investor selects automatic or manual mode.
    \item In automatic mode, the system derives the analytical configuration from the saved investment horizon; in manual mode, the investor toggles the news and fundamental sources, selects one or more technical indicators, and assigns source weights.
    \item The client and backend validate the completed configuration.
    \item The investor submits the analysis request.
    \item The multi-agent workflow prepares and analyzes the enabled technical, fundamental, and news evidence.
    \item The recommendation stage calculates the weighted total, applies the 0.60 total-score threshold and the horizon-specific technical threshold, conditionally bypasses the technical gate when its manual weight is below 0.15, and creates a trading plan for an accepted \textit{Buy}.
    \item The aggregator generates a bounded confidence assessment and summary without changing the established decision or trading plan.
    \item The application presents the action, confidence, component evidence, explanations, and any applicable risk-related values.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item Invalid manual weights or a configuration with no selected technical indicator are blocked before execution.
    \item Unavailable evidence is marked missing; its component score defaults to zero, and the aggregator may reflect the missing evidence in its confidence assessment.
    \item A weighted total below 0.60, or a technical score below the applicable horizon minimum when that gate is active, produces \textit{Wait}; confidence does not override this decision.
    \item A provider, validation, or data error produces controlled feedback and does not create a partial recommendation object.
\end{itemize}

\subsection{Conversational Financial Assistant}
\label{subsec:conversational-financial-assistant}

\noindent\textbf{Use Case Name:} Ask and Continue a Financial Question

\noindent\textbf{Actor:} Authenticated Investor

\noindent\textbf{Pre-Condition(s):} The investor has a valid session. The backend, conversation store, and required model or financial-data services are available.

\noindent\textbf{Post-Condition(s):} The question and generated answer are appended to the investor's conversation, and the updated conversational state is checkpointed for later continuation.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The investor opens the conversational assistant.
    \item The investor creates a conversation or selects an existing session.
    \item The investor enters and submits a natural-language financial question.
    \item The system loads the applicable conversation state and selects the required financial information or tools.
    \item The assistant generates an answer based on the available context.
    \item The backend stores the updated checkpoint and the application displays the answer.
    \item The investor may continue with additional turns.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item The investor reopens a previous session from conversation history or deletes a session that is no longer needed.
    \item An empty or invalid question is blocked before submission.
    \item Missing data or an unavailable provider produces a bounded explanation or controlled error rather than an unsupported fabricated record.
\end{itemize}

\subsection{Stockrium Lab Experimentation and Comparison}
\label{subsec:experimentation-backtesting}

\noindent\textbf{Use Case Name:} Run, Review, and Compare Stockrium Lab Experiments

\noindent\textbf{Actor:} Authenticated Stockrium Lab User

\noindent\textbf{Pre-Condition(s):} The user has a verified Stockrium account and an active authenticated session. The protected backend, historical data, and selected analytical services are available, and the requested configuration is within the supported scope.

\noindent\textbf{Post-Condition(s):} A user-owned analysis or backtesting experiment records its name, type, scope, configuration, status, summary, detailed result or result reference, and available reproducibility metadata. The result can be revisited and, when compatible, compared with other experiments. No live-market order or portfolio transaction is performed.

\noindent\textbf{Basic Path:}
\begin{enumerate}[leftmargin=*, nosep]
    \item The user signs in and opens Stockrium Lab.
    \item The user enters an experiment name and selects AI analysis or historical backtesting.
    \item For analysis, the user selects one stock, VN30, or VN100 and the supported analytical inputs; for backtesting, the user selects one stock or VN30, the historical period, and supported simulation parameters.
    \item The interface validates the configuration and submits the authenticated request.
    \item The backend creates a user-owned experiment. Analysis completes within the request, while backtesting returns an experiment identifier and continues as a background task.
    \item The user monitors batch progress or experiment status until the run completes or fails.
    \item The user opens the stored experiment to inspect the configuration, structured analyses, simulated trades, measures, references, and available visualizations, or exports a supported CSV summary.
    \item The user may select from two to five saved experiments of the same type and compare their configurations and results side by side.
    \item The user interprets the comparison as descriptive evidence of pipeline behavior and returns to Stockrium Lab.
\end{enumerate}

\noindent\textbf{Alternative Paths:}
\begin{itemize}[leftmargin=*, nosep]
    \item The user filters experiment history by type or status and opens a stored result instead of starting a new run.
    \item Invalid dates, thresholds, holding limits, analytical selections, or unauthenticated requests are rejected before execution.
    \item Experiments of different types, records owned by another user, duplicate selections, or selections outside the two-to-five comparison limit are rejected.
    \item A failed analysis or backtest remains visible with a failed status and error information rather than being presented as a successful result.
    \item A batch run records a symbol-level failure without presenting the failed symbol as a successful result; a compatible rerun may resume completed VN30 work and retry failed symbols.
    \item If optional artifact upload fails after a completed backtest, the simulation result and experiment status remain available through the protected application workflow.
\end{itemize}

Together, these use cases define Stockrium as a configurable and explainable decision-support and experimentation environment. They connect market discovery, evidence inspection, multi-agent synthesis, independent conversational assistance, and user-driven experiment comparison while keeping investment decisions and any subsequent transactions under the user's responsibility.
