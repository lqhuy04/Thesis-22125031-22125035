\section{Application Idea}
\label{sec:application-idea}

Stockrium is proposed as a decision-support platform that helps individual investors examine Vietnamese listed companies without collecting information from many disconnected sources. The mobile application guides the user through a continuous process of discovering a stock, reviewing market and company information, configuring an analysis, receiving a multi-perspective assessment, and investigating the supporting evidence. Technical, fundamental, and news perspectives remain distinguishable so that the recommendation is presented as an explainable synthesis rather than an unexplained prediction.

The project also provides an administrative web interface for controlled analysis and historical backtesting, together with a curated dataset covering price and volume history, company fundamentals, and financial news with sentiment labels. Stockrium remains analytical rather than transactional: it does not place securities orders, transfer funds, or connect to brokerage firms. Any investment action following an analysis remains the user's responsibility.

\subsection{Stakeholders}
\label{subsec:application-stakeholders}

The proposed system considers four principal stakeholder categories. Individual investors are the primary users, while the administrator operates system and experimental functions through the restricted web interface. A securities analyst contributes practical evaluation, and technical teams and service providers support the data and software infrastructure.

Beginner and experienced investors are treated as profiles within the same stakeholder group rather than as different account roles. Beginners may rely more on default configurations and explanations, whereas experienced users may inspect individual evidence sources and adjust the analytical configuration.

\subsection{Main Application Flows}
\label{subsec:main-application-flows}

The use cases form two primary experiences: an investor-facing mobile journey and an administrative workflow. These flows describe user-visible behavior and intentionally treat the internal agent system as a single analytical service; its nodes, state, and execution logic are presented in Chapter 4.

\subsubsection{Mobile Exploration and Stock-Analysis Flow}

A guest first completes onboarding and authenticates through registration, password sign-in, or the supported Google Sign-In flow. After authentication, the investor can enter a stock context from the market overview, search, financial news, or the watchlist. The stock-detail view consolidates price and volume charts, company information, fundamental data, technical indicators, and related news, allowing the investor to examine the available evidence before requesting an assessment.

The user may proceed with an automatic analysis configuration or manually select the evidence sources and their relative weights. The request combines the selected configuration, stock symbol, and saved investment horizon. Figure~\ref{fig:stockrium-primary-flow} summarizes the first part of the mobile journey, from account access and stock discovery to submission of the analysis request.

The result includes confidence and source-specific explanations; an accepted \textit{Buy} assessment may additionally contain an entry price, take-profit price, stop-loss price, and maximum holding period. The recommendation is not the final step of the user journey. The investor can return to the supporting charts and company data, revise the configuration, update the watchlist, or ask a contextual question. These paths form an iterative cycle in which the user continues to examine the evidence rather than acting solely on the generated action label.

\subsubsection{Conversational Follow-up Flow}

The conversational assistant supports both independent financial questions and follow-up questions about an existing analysis. An authenticated investor may create or revisit a conversation, submit a Vietnamese natural-language question, receive an answer based on available system information, and continue with additional turns. The assistant helps explain terminology and analytical evidence, but its answers remain informational and are subject to the same data and model limitations as the main analysis.

\subsubsection{Administrative Analysis and Backtesting Flow}

The administrator uses the internal web interface for controlled analysis and historical evaluation. AI-assisted analysis can be requested for an individual stock or for the VN30 or VN100 universe. Backtesting can be executed for an individual stock or sequentially for the VN30 universe. The administrator can monitor batch progress and inspect or export the resulting reports. A completed backtest presents price charts, generated entries and exits, performance and risk measures, and relevant analytical results. Together with the mobile journey, it positions Stockrium as an evidence-centered application and a controlled environment for evaluating Stockrium's analytical pipeline and supported configurations.
