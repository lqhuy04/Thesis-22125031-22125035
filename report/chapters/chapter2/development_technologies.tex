\section{Development Technology Foundations}
\label{sec:development-technology-foundations}

Stockrium consists of mobile and web interfaces, a backend application programming interface (API), data pipelines, persistent storage, and multi-agent analysis workflows. This section introduces the principal technologies used in these components and the responsibility of each technology within the system.

\subsection{Frontend Technologies}

\textbf{Mobile application.} The mobile client for individual investors is developed with React Native, React, and TypeScript. React supplies the component model, React Native maps components to native mobile user-interface (UI) elements \cite{reactnative2026}, and TypeScript adds static types for market data, financial information, and analytical results. Expo supplies the development runtime and device services, while Expo Router maps files to application routes and navigation paths \cite{expoRouter2026}. Reanimated and Gesture Handler support responsive animation and touch interaction.

\textbf{Experimentation web interface.} The internal experimentation and backtesting web interface is implemented with HyperText Markup Language (HTML), Cascading Style Sheets (CSS), and JavaScript. It communicates with protected backend endpoints to support controlled analysis over selected stock groups, internal backtesting, progress monitoring, and result inspection. The interface is intended only for authorized evaluators and is not deployed as a public web application.

\textbf{Data visualization.} TradingView Lightweight Charts is embedded through React Native WebView, which hosts web content inside a native screen, to display interactive candlestick, volume, and recommendation charts \cite{tradingviewLightweight2026}. Victory Native provides reusable chart components, React Native Skia supplies accelerated two-dimensional drawing \cite{reactNativeSkia2026}, and Wagmi Charts supports interactive time-series and indicator lines. Data-Driven Documents (D3) Hierarchy calculates the nested rectangular layout used by the market treemap. These libraries allow each financial visualization to use a rendering approach suited to its data and interaction requirements.

\subsection{Backend Technologies}

The backend is implemented in Python with FastAPI and served by Uvicorn, an Asynchronous Server Gateway Interface (ASGI) server. FastAPI defines Representational State Transfer (REST) endpoints over the Hypertext Transfer Protocol (HTTP), supports asynchronous request handling, and generates interactive API documentation \cite{fastapiFeatures2026}. Pydantic models validate the structure and type of request and response data \cite{pydanticModels2026}, while Pydantic Settings loads configuration and credentials from environment variables \cite{pydanticSettings2026}. Requests and HTTPX provide HTTP clients for external services. The source code follows a route--service structure: routes handle transport concerns, services implement application logic, and service or utility clients communicate with Supabase, SSI, and other external providers. The backend is deployed on Railway, a cloud application-hosting platform.

Authentication uses bcrypt, an adaptive one-way password-hashing algorithm, so plaintext passwords are not stored. PyJWT creates and verifies signed JSON Web Tokens (JWTs): short-lived access tokens authorize API requests, while refresh tokens obtain new access tokens without requiring the user to enter credentials again. Server-side session records in Redis allow issued tokens to be checked and invalidated, while Expo SecureStore protects token values stored on the mobile device \cite{expoSecureStore2026}. The system also supports Google Sign-In, time-limited one-time passwords (OTPs) for account verification and password recovery, and transactional email delivery through the Resend HTTP API \cite{resendApi2026}. Secrets, provider credentials, and API keys are kept in environment configuration rather than embedded in source code.

\subsection{Data Acquisition, Processing, and Storage Technologies}

SSI Securities Corporation's FastConnect (FC) Data services provide Vietnamese security, price, and market-index data through historical APIs and real-time WebSocket streams. A WebSocket maintains a persistent connection for receiving continuous market updates, unlike repeated request--response polling. The WebSocket listener and the scheduled SSI API calls run as long-lived and periodic processes deployed on Railway. Supabase Edge Functions provide server-side functions for executing data-processing and integration tasks, while Supabase Cron invokes such functions automatically on configured schedules. Stockrium uses this mechanism to call two Edge Functions that retrieve current stock-price and market-index data from SSI and update the corresponding data in Supabase. This scheduled design keeps application-facing market information current without performing external acquisition synchronously in a mobile request. Offline utilities use Selenium WebDriver to automate the dynamically rendered SSI iBoard interface and collect company profiles and financial reports \cite{seleniumWebDriver2025}. The news pipeline uses Serper to discover relevant pages and Newspaper3k to extract article text before OpenAI-based summarization and sentiment labeling.

pandas represents and transforms tabular data, NumPy provides numerical arrays and calculations, and OpenPyXL allows pandas to read downloaded Microsoft Excel workbooks. Stockrium's active technical-indicator service implements moving averages, RSI, MACD, Bollinger Bands, KDJ, and volume averages directly with pandas and NumPy, while SciPy supplies statistical functions for backtest evaluation \cite{pandasIO2026}. These acquisition and preparation pipelines populate the database independently of ordinary mobile requests; they are not executed synchronously when a user opens a screen.

Supabase provides the principal PostgreSQL relational database for account, market, company, fundamental, news, and chatbot data \cite{supabaseDatabase2026}. PostgreSQL uses Structured Query Language (SQL) for relational data operations. The Supabase client supports ordinary table access, whereas Psycopg provides direct PostgreSQL connections for LangGraph checkpoint persistence and related chat operations. Supabase Storage stores exported JavaScript Object Notation (JSON) backtest artifacts when they are uploaded. Redis supplies expiring key--value storage for short-lived authentication data, including token sessions, OTPs, attempt counters, and password-reset sessions \cite{redisDataTypes2026}; it is not the primary store for market or financial records.

\subsection{Multi-Agent Orchestration and State Management Technologies}

Two large-language-model providers support Stockrium's language-based components. The news-acquisition pipeline and the conversational chatbot use the OpenAI Python software development kit (SDK) to call GPT-4o mini for article summarization, sentiment labeling, and chatbot responses, constrained via OpenAI Structured Outputs with Pydantic schemas \cite{openaiStructuredOutputs2026}. The stock-analysis graph instead reaches DeepSeek's \texttt{deepseek-v4-flash} through the same OpenAI-compatible SDK pointed at DeepSeek's application programming interface (API): each specialist and the aggregator request DeepSeek's JSON-object mode with the target Pydantic schema embedded in the prompt, and the returned JSON is validated against that schema in application code. Schema compliance improves interoperability but does not prove factual correctness, regardless of provider. Numerical indicators, weighted recommendation scores, decision thresholds, and trading-plan validation remain in deterministic Python code, while the aggregator generates a bounded confidence assessment and explanation after the Buy-or-Wait decision has been established.

LangGraph coordinates the orchestrator, specialist analytical nodes, aggregator, and chatbot through explicit stateful graphs, while LangChain Core supplies supporting message abstractions. During stock analysis, a typed shared state carries the request, execution plan, retrieved source data, and branch results. Reducers define how concurrent updates are combined, allowing the technical, fundamental, and news branches to merge their outputs before aggregation without overwriting one another. For the chatbot, LangGraph checkpoints save graph state by session in PostgreSQL through Psycopg, allowing a later request to resume the correct conversation \cite{langgraphPersistence2026}. A checkpoint is a durable snapshot of workflow state, whereas the in-memory shared state exists only during an individual execution. This distinction separates temporary coordination data from persistent conversation history.
