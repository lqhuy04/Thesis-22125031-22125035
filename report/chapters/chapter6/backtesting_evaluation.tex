\subsection{Saved Configuration}
\label{subsec:illustrative-vn30-configuration}

The selected saved run contains the 30 symbols returned by Stockrium's current VN30 lookup. It was requested for August~1, 2024 through August~1, 2026 using daily candles, a request-level holding limit of 20 candles, and the backend transaction-cost assumption of 0.15\% per side. Full-pipeline trades can instead use valid recommendation-generated holding, take-profit, and stop-loss values. \label{subsec:illustrative-user-comparison}

The saved full pipeline produced fewer trades, a slightly higher median return, and a mean drawdown closer to zero than the engine-only path, while its mean return was slightly lower. It exceeded the same-security buy-and-hold return for only 3 of 30 symbols; the buy-and-hold mean and median returns were 76.38\% and 36.86\%, respectively. These mixed values are useful in the interface because they encourage the user to inspect more than one measure. They do not establish superiority: the two simulated paths also use different decision and trade-management rules, and buy-and-hold represents continuous exposure without the simulator's transaction-cost deduction.

The Lab can additionally display confidence groups, market-regime summaries, statistical fields, and single-indicator companion runs. In this saved case, results vary by security and no one technical indicator dominates every displayed measure. The purpose of retaining these views is to make assumptions and variation inspectable, not to select a universally best configuration from one historical interval.

\subsection{Saved History and Reinspection}
\label{subsec:saved-history-reinspection}

After completion, the user does not need to preserve only a screenshot or downloaded total. Stockrium Lab retains an owned experiment record containing its name, type, scope, mode, status, configuration, reproducibility information, result summary, detailed data or artifact reference, timestamps, and duration. The history page can reopen this record, and the comparison page can load two to five owned records of the same type in the requested order. Consequently, the case demonstrates the end-to-end user task of running, retaining, inspecting, and comparing an output rather than merely executing a backtest once.
