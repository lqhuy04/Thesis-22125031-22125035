\section{Purpose and Representative User Scenario}
\label{sec:lab-usage-purpose}

This chapter presents one representative use of Stockrium Lab. Its purpose is to show how an authenticated user can configure a historical backtest, monitor its execution, reopen the saved record, inspect its assumptions and outputs, and compare it with available references. The walkthrough is a concrete demonstration of the implemented tool, not a formal experiment intended to prove that Stockrium produces superior or profitable investment decisions.

The scenario uses the VN30 batch workflow because it exercises the principal Lab capabilities over more than one security. The user performs the following steps:

\begin{enumerate}
    \item sign in and select the backtest workspace;
    \item choose the VN30 scope, daily historical period, supported analytical configuration, holding limit, and exit options;
    \item submit the run and observe symbol-level progress while the backend creates and updates owned experiment records;
    \item open the completed record from personal history to inspect its configuration, reproducibility notes, metrics, trades, and visualization data; and
    \item compare the saved output with the engine-only and same-security buy-and-hold references, or select other compatible records for side-by-side comparison.
\end{enumerate}

This flow reflects the role division established earlier in the thesis. The mobile application supports routine stock exploration and individual analysis, whereas Stockrium Lab uses a larger web workspace for information-dense results and operations that may continue after the initiating request returns. Every history, detail, comparison, and artifact request remains scoped to the authenticated user.

The saved case uses current database contents and model-backed analysis. Its reproducibility metadata can identify the submitted configuration and disclose important limitations, but it cannot make live upstream data or nondeterministic model output identical in every rerun. The values below are therefore treated as one saved example that a user can inspect, not as universal properties of the analytical pipeline.
