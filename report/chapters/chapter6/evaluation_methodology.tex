\section{Evaluation Methodology}
\label{sec:evaluation-methodology}

The evaluation examines the historical behavior of Stockrium's analytical pipeline. Its purpose is to determine how the complete multi-agent pipeline behaves relative to explicit alternatives, how sensitive the results are to securities and market conditions, and whether the available evidence supports a reliable performance claim. It does not treat historical profit as a guarantee of future return.

Three evaluation questions guide the chapter:

\begin{enumerate}
    \item \textbf{EQ1: Comparative performance.} How does the complete multi-agent pipeline compare with the engine-only technical strategy, passive buy-and-hold exposure, and random entry timing?
    \item \textbf{EQ2: Robustness and calibration.} Are results consistent across VN30 securities, technical indicators, confidence tiers, and market regimes?
    \item \textbf{EQ3: Statistical and practical validity.} What statistical evidence supports non-zero outcomes or superiority to the stated alternatives, and which data or simulation limitations constrain interpretation?
\end{enumerate}

\subsection{Evidence Sources}
\label{subsec:evaluation-evidence-sources}

The primary evidence consists of JSON artifacts produced by the backtesting framework described in Section~\ref{sec:backtesting-framework}. The latest complete-pipeline aggregate contains pipeline and engine-only metrics, buy-and-hold and random comparisons, statistical tests, confidence summaries, and regime results for the 30 securities returned by the current VN30 lookup. The contributing batch was requested for August~1, 2024 through August~1, 2026, although the aggregate does not store one immutable top-level run manifest. Five companion artifacts contain engine-only ablations for RSI, MACD, KDJ, Bollinger Bands, and moving-average conditions over the same explicitly recorded requested interval and symbol set. The regenerated ablations load pre-start history, preserve the common 50-candle warm-up, and trim to the evaluation interval only after scoring. Each artifact records these settings and reports 30 successful symbols with no error.

Source inspection is used only to establish how the artifacts were produced: every date meeting the fixed technical threshold becomes a candidate; the deterministic Buy-or-Wait rule determines which candidates proceed; the full pipeline supplies take-profit, stop-loss, and holding-period overrides; execution begins at the next open; stop loss is checked before take profit within a daily candle; and 0.15\% transaction cost is deducted on each side. Confidence is generated after the decision and is retained for grouping, not used as an execution gate. This inspection is necessary because an evaluation is meaningful only when the execution assumptions behind its metrics are stated clearly.

\subsection{Measures and Comparisons}
\label{subsec:evaluation-measures-comparisons}

Performance is summarized by trade count, win rate, total return, maximum drawdown, and the implemented trade-level Sharpe statistic. Cross-sectional means and medians are reported separately because a small number of securities contain sparse or extreme values. The full pipeline is compared with the engine-only branch on the same scored daily frame. However, the full branch changes both candidate acceptance and trade management through recommendation-generated price boundaries and holding periods, whereas the engine branch uses technical candidates and the request-level holding limit without those price boundaries. The comparison therefore measures the combined effect of the multi-agent decision and trading-plan layer; it does not isolate candidate filtering, any single evidence branch, or confidence.

Buy-and-hold provides a passive same-security reference and is calculated without the simulator's transaction-cost deduction. The random-entry reference places pipeline return within 1,000 simulations that sample as many signal dates as the number of completed pipeline trades, apply the same transaction cost, and use a fixed 20-candle hold without recommendation-generated price boundaries. Position overlap can reduce the number of random trades actually executed. One-sample $t$-tests and sign-permutation tests examine whether per-trade outcomes differ from zero; they are not paired tests against engine-only or buy-and-hold performance. Confidence groups and VN-Index regimes provide descriptive robustness views. Single-indicator ablations show whether results depend disproportionately on one technical perspective.

Repeated historical comparisons can produce backtest overfitting \cite{bailey2017pbo}. Accordingly, this chapter reports unfavorable and non-significant results, distinguishes descriptive metrics from statistical evidence, and treats limitations in point-in-time data, universe construction, execution, and experiment metadata as part of the findings rather than as implementation details to omit.
